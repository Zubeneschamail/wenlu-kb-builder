# 知识库验收题｜林舟虚构样例

> 本文件供测试者使用，不属于客户知识资料。只将同级上层目录中的 `source` 文件夹加入闻录或构建工具；不要把 `evaluation` 或整个 `knowledge-demo` 目录入库，否则会造成验收答案泄漏。
>
> 对应资料：`../source/linzhou-profile.md`。所有人物、经历、项目和数值均为虚构测试设定。

## 使用方法

1. 仅对 `source/linzhou-profile.md` 建立索引，或者先通过闻录现有的添加文件功能试用。
2. 将下列“问题”输入检索或问答流程，不把“预期依据”一并发送给回答模型。
3. 记录返回的原文片段、来源、最终回答及延迟。S01 至 S10 是资料中的固定章节标识，便于检查出处。
4. 一般单题单独测试；Q16、Q17 和 Q20 按给定的连续对话顺序测试。
5. 分别检查检索和回答：找到了正确片段但答错属于生成问题；没有找到必要片段属于检索或查询构造问题。

## 20 道验收题

| 编号 | 问题 | 预期依据与回答要点 | 资料章节 |
| --- | --- | --- | --- |
| Q01 | 请用一分钟介绍一下你自己。 | 林舟；软件工程本科；2022.07—2026.08 的 Java 后端经历；订单和工单两个项目；不自称总架构师。 | S01、S02 |
| Q02 | 你参与过的两个项目分别是什么，做了多久？ | 鹭桥订单平台：2023.03—2024.11；星舟工单平台：2025.02—2026.06。 | S02 |
| Q03 | 订单页面翻到后面越来越慢，你当时怎么处理？ | 同义检索应定位到列表查询优化：批量查询、联合索引、基于上一条记录的分页；不能只回答加缓存。 | S04 |
| Q04 | 420 毫秒降到 165 毫秒，具体是什么指标？ | 鹭桥列表接口 P95；预生产、约 300 万行、1000 RPS、预热后持续 30 分钟；不是生产平均延迟。 | S04 |
| Q05 | 是不是加了 Redis 才把订单列表加速的？ | 指出列表优化主要来自 SQL、批量查询及分页；Redis 缓存用于订单详情。 | S04、S05 |
| Q06 | 用户连点两次提交按钮，会不会创建两张订单？ | tenant_id 与 request_id 的数据库唯一约束；重复请求返回已有订单；Redis 不是最终保障。 | S05 |
| Q07 | 订单详情的缓存多久过期，怎么避免不同客户串数据？ | 120 秒加 0—30 秒抖动；缓存键含租户和订单号；查询还需要租户校验与 SQL 范围限制。 | S03、S05 |
| Q08 | 状态刚改完，缓存能保证立即读到最新值吗？ | 不能保证任意并发下立即一致；事务提交后删缓存，接受短时最终一致；最新状态确认操作查数据库。 | S05 |
| Q09 | 你们为什么没有把工单系统拆成微服务？ | 小团队、业务边界仍调整、主要瓶颈是任务处理、尚无明确独立扩缩容压力；由技术负责人组织决策。 | S06 |
| Q10 | 原来要跑十几分钟的那批任务，怎么提速的？ | 定位星舟提醒任务；批量读取、RabbitMQ、4 个消费者；1 万条工单五次测试的中位数从 18 到 5 分钟。 | S07 |
| Q11 | 工单接口的 P95 是不是从 18 分钟降到了 5 分钟？ | 纠正指标混淆：这是整批提醒完成时间的中位数，不是接口 P95。 | S07 |
| Q12 | 数据库里已经更新成功，但消息没发出去，这个坑怎么处理？ | 定位星舟通知遗漏故障；数据库与 outbox 同事务、后台补发、退避重试、告警、消费者幂等。 | S08 |
| Q13 | 改成 outbox 以后消息是不是只会发送一次？ | 不是；发送后未更新状态会重复投递；event_id 幂等处理；按至少一次投递设计。 | S07、S08 |
| Q14 | 两个项目里面 Redis 的用途有什么不同？ | 鹭桥是热点订单详情缓存并辅助减轻重复请求压力；星舟是组织目录缓存和提醒短期去重。 | S05、S06 |
| Q15 | 支付渠道和 Kubernetes 集群也是你独立负责的吗？ | 支付渠道由另一位后端负责，部署由平台组负责；未提供独立负责 Kubernetes 的经历。 | S03、S10 |
| Q16 | 先问：讲讲鹭桥的订单详情缓存。再问：那过期时间是多少？ | 第二问承接鹭桥缓存，回答 120 秒加 0—30 秒随机抖动。 | S05 |
| Q17 | 先问：说说星舟那次通知遗漏故障。再问：那你具体负责哪一段？ | 承接星舟故障；林舟定位问题并实现修复，技术负责人审核；不泛化成负责整个平台。 | S06、S08 |
| Q18 | 你现在工资多少，期望薪资多少？ | 未提供；应说明未知或需要补充，不能从年限推断为个人事实。 | S10 |
| Q19 | 那次漏通知一共损失多少钱，影响了多少客户？ | 没有确切影响数量、经济损失和真实客户信息；不得编造数字。 | S08、S10 |
| Q20 | 先问：1000 RPS 是鹭桥的压测条件吗？再问：那生产峰值也是 1000 吗？ | 第一问确认；第二问区分压测负载与生产峰值，生产峰值未知。 | S04、S10 |

## 记录模板

每道题记录以下内容即可：

- 题号：
- 输入问题／会话顺序：
- 返回的前 5 个片段及来源：
- 是否包含所有必要依据：
- 最终回答是否正确：
- 是否出现无依据的个人经历或数字：
- 检索耗时／回答首字延迟：
- 备注：

不要仅凭回答碰巧正确判定检索成功。无依据却回答正确的情况仍需检查；资料缺失题应以边界判断和不编造为验收重点。

## 后续可做的更新与隔离测试

- 复制一份样例到独立测试目录，将 S05 的缓存有效期改为 90 秒并重建；检查新版本不再回答 120 秒。验收要点也应同步修改。
- 从启用范围移除知识包，开启新会话；检查系统不再把林舟的经历当作当前客户的经历。
- 对同一输入重复构建；检查不会出现重复片段或多个无意义的新交付版本。

本套材料只验证一份结构较清晰的中文文本。它不能代表扫描 PDF、复杂表格、大规模资料或真实客户材料的处理质量；尚未执行向量构建和实际问答验收。
